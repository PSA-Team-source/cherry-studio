# 记忆存储底座

本模块实现 [共享记忆 Spec](../../../../.agents/notes/proposed/feature/2026-10-29-shared-memory.md) 的文件提交、访问权限、入口加载、编辑、最近操作恢复、旧 FACT 迁移和 Dreaming。Pi 已接入受控读取、写入和编辑。后续测试按用户要求跳过，行为验收尚未完成，Spec 保持 proposed。

- `MemoryStore.ts`：一个作用域由一个实例串行提交。调用方身份使用主进程持有的 `MemoryAccess` 对象，不能从模型或 IPC 输入反序列化。
- `MemoryService.ts`：生命周期服务。按作用域复用存储实例，绑定调用方凭据，提供暂停、排空和恢复失效入口。
- `memoryAuthority.ts`：从主进程会话、实体配置和受管理窗口确定权限。每次操作重查数据库，不接受模型提供的身份。
- `memoryPrompt.ts`：按当前权限读取入口，标明截断和未加载的主题。加载后释放会话，组装引用前再次检查权限。
- `memoryTarget.ts`：识别请求路径和真实目标中的受管理文件，阻止通过普通文件工具读取恢复备份。
- `MemoryEditorService.ts`：把编辑会话绑定到主窗口。窗口关闭后释放会话，其他窗口不能复用凭据。
- `MemoryMigrationService.ts`：串行迁移私有 FACT，备份原文并核对目标后才启用。`legacyMemoryPlan.ts` 保留完整 Markdown 小节，不能安全拆分时停止迁移。
- `MemoryDreamingService.ts`：维护单个全局整理队列、代次、取消和空闲检查。`memoryDreamingState.ts` 独占永久复核元数据；模型调用与提案校验分别在 `memoryDreamingModel.ts`、`memoryDreamingPlan.ts`。
- `memoryFiles.ts`：管理文件白名单、真实路径、完整读取、容量检查和文件替换。
- `memoryBackups.ts`：保存原始字节、预期哈希和逐项结果。备份位于活动目录之外。

服务从路径注册表获取根目录。私有范围检查现有 Agent 目录。`read()` 返回完整正文与调用方绑定的凭据。`entry()` 可能截断，因此不返回编辑凭据。

Agent 的 `configuration.shared_memory_enabled` 缺省为开启。持久助手的 `settings.enableSharedMemory` 缺省为关闭。临时、辅助和普通 headless 助手不开放记忆。渠道 Agent 只能访问所属私有范围。编辑器要求真实的主窗口身份。Pi 在新轮次、结束和关闭时释放文件会话及读取关联。

关闭共享开关后，旧会话凭据不会因重新开启而恢复。实体数据服务只发布权限失效事件，文件操作仍归本模块。完整备份已接入 `pause()` 和 `drainInFlight()`；恢复提交启动日志后调用 `invalidateAll()`，保持暂停直到重启。

Pi 在每次模型请求前替换 `cherry_memory` 系统区块，保留其他提示词和工具声明。Claude Code 在 `UserPromptSubmit` 和 `SessionStart` 提供完整引用，空引用撤回先前内容。已发送的上下文不能收回。助手入口仅接受持久聊天 owner 创建的主进程 `memoryContext`，每次 `prepareStep` 重新读取，覆盖压缩后的请求。入口引用不代表获得保存能力。

Pi 的原生 `read`、`write`、`edit` 在执行入口调用原有审批器。受管理完整读取返回 `memoryReceipt`，修改必须显式带回同一轮次、同一文件的凭据。编辑继续使用 SDK 的替换算法，但最终保存归 `MemoryService`。审批带准确的完整提案；审批中编辑输入后需重新发起操作，不能沿用旧提案。最终替换前检查权限、取消、工具开关和审批模式。普通文件继续走原工具。

Claude Code 的原生钩子尚不能提供完整执行接管，因此拒绝命中受管理记忆的原生文件操作和包含它的搜索。没有调用方身份的内置 filesystem MCP 也拒绝受管理目标、恢复备份和相关目录操作。Shell 与外部工具仍不属于保护范围。当前未提供原生删除、重命名或主题搜索能力；这些能力不能宣称已完成验收。

Pi 的可选 grep、find 和 ls 也拒绝受管理目标及其祖先目录，防止 SDK 动态启用这些工具后绕过主题读取边界。审批中改动搜索目标后再次检查。

设置页 `/settings/memory` 编辑共享范围。Agent 设置可打开自身私有范围。文件操作使用 `memory.*` IpcApi 路由；实体开关沿用 DataApi。页面以正文和主题切换为主，维护操作收进“更多”菜单。保存冲突保留草稿，清空和恢复先展示文件集与冲突结果。只在操作未完成时显示相关文件，不常驻展示容量、路径和逐文件成功结果，不自动重试写入。

入口注入最多读取 25001 字节，再按完整行截取。完整读取预算为 20 MiB；超出预算时保留原文件并拒绝颁发编辑凭据。

`commit()` 向权限层提供不可修改的准确提案。权限层返回授权存续检查。自动批准仍需此检查。撤销调用方权限时调用 `invalidate(access)`；清空、恢复或删除作用域时使整个作用域失效。

授权存续检查必须同步执行，临时文件准备完毕、替换前再次调用。整理提交通过 `readReceipts` 绑定全部输入，即使其中部分文件不修改或整批无需修改。

`previewClear()` 只保留已展示的文件集、哈希和读取凭据。`clear()` 在作用域锁内复查文件集和版本；新出现的受管理文件会使确认失效。清空保留空入口、未知文件和历史文件，并生成可恢复批次。

原生工具适配器必须保留真实读取与具体编辑的关联。不能把最近一次读取凭据自动套给更早的编辑。工具截断了正文时，不能将该次读取用于编辑。

备份清单使用 JSON，原始字节以 Base64 保存。20 MiB 限额按实际清单字节计算，包含编码开销。文件与 SQLite 不构成同一事务。恢复检查磁盘结果，不重放旧操作。

混合已提交、未提交或冲突的批次保留为 partial，不进入自动配额清理。恢复前也先保护原批次。只有全部恢复成功且没有冲突时才解除该保护，避免新恢复批次取代它后丢失剩余原文。准入时为新旧批次都预留最长状态文本的空间，避免恢复状态变长后超过容量。

迁移批次可额外保存旧 FACT 的原始字节和哈希，仍计入同一容量限制。该原文不是受管理恢复目标，不能伪装成新入口修改前的内容。提交前和锁内都检查旧 FACT 基准。`initializeMemoryFiles()` 统一初始化活动文件，供 Agent 目录 owner 复用；不覆盖已有正文。

完整备份在首个写入前落盘，结果在批次完成或失败时保存。避免每写一个文件就重复序列化整批原文。崩溃留下的 pending 步骤按实际哈希复核，不重放。只读旧 FACT 回退可复用有界入口读取，不产生编辑凭据。

迁移状态由本模块独占的 `app_state` 键保存，只有文件名、哈希、批次引用和状态。完整迁移退出旧 FACT 注入。失败保留只读旧事实，新私有范围不启用；不会重放部分完成的旧计划。重新打开私有编辑页可重试，混合版本需先处理恢复。旧 Agent Memory MCP 停止挂载，JOURNAL 不再追加；原生文件和内置 filesystem 工具也拒绝历史目录。旧文件、身份文件、独立图谱 MCP 和知识库保留。

Dreaming 默认开启，使用应用默认模型。`memory.dreaming` 处理器在初始化时注册，恢复策略为 abandon，所有作用域共用并发为 1 的队列。只有一个每分钟唤醒的持久调度，错过时间点不补跑。每次轮转检查一个作用域的入口和最多九个主题，优先处理已变化且符合条件的文件。未选中文件不推进已处理标记。

十次受控内容修改、最早待处理变化七天、变化后的容量预警或手动请求触发整理。旧文件观察使用哈希，不从哈希推算修改次数。无修改、失败、Dreaming 和恢复不增加计数。每份未变输入最多尝试两次，间隔十分钟；新内容、明确手动请求或更换默认模型提供新的机会。永久标记只存哈希、时间、计数、代次和短状态，不依赖任务历史，也不保存正文。

模型输入不超过十个完整文件和 50,000 UTF-8 字节。再按模型声明的上下文、输入和输出上限缩小批次；容量未知或不足时停止。每批只调用一次模型，关闭工具、自动重试和上下文裁剪，不传聊天、JOURNAL、身份文件或其他作用域内容。推理不持有文件写锁。

提交复查全部输入凭据。删除还在锁内复查完整活动文件集，要求原文已逐字保存在同目录主题目标，并检查剩余 Markdown 和 wiki 链接；HTML 链接交给人工处理。先写目标和链接，再删来源。成功文件才更新进度，失败保留恢复资料。程序不证明模型改写语义等价。

清空、恢复、暂停和完整恢复通过 `MemoryService.onInvalidated` 先撤销尚未提交的维护输出。关闭自动整理、手动取消、Agent 删除和重启也使旧代次失效。前台对话开始后取消当前模型调用，后续提交仍同步检查空闲状态。设置仅增加自动开关、整理/取消操作、上次时间和需处理的失败；不展示内部队列、计数或容量参数。

该保护只覆盖经过本模块的写入。外部编辑、Shell 和其他直接磁盘访问不受作用域锁约束。当前测试覆盖 Windows；其他平台原生文件检查仍需补齐。
